# 0.1.9 升级提示验证

## 原因与修复

0.1.8签名更新说明复用了整份GitHub下载页，旧界面又按普通文字显示，导致Markdown、表格和长链接直接出现在弹窗里。原有进度和错误还位于说明滚动区内部，长说明会把状态挤出可视区域。

- 新客户端原生排版更新摘要，优先提取旧0.1.8说明的“本版改进”，其余历史说明按格式显示并限制长度；不加载图片或执行HTML／代码。
- 版本号、预发布标记、状态、进度和操作独立展示。安装／待重启时收起改动清单；错误和操作保持可见。
- App签名元数据改用`packaging/update-notes.txt`的短列表，网页继续使用`release-notes.md`。签名格式和安装保护不变。发布器验签后逐平台核对App说明，防止再次误签网页全文。

## 本地与独立复核

真实0.1.8说明的原生回归先复现源码直接显示；长说明下状态位置超过窗口两万像素，测试失败。修复后相关测试及完整Go套件、`go vet`、登录脚本、21项打包测试、actionlint和公开源码隐私扫描通过。

检查浅色、深色、NGA经典屎黄色，以及980×620／760×520窗口。独立只读复核另外组合了长下载错误、残留进度、未记住登录提醒、手动下载原因、重启保存失败和安装退出提醒，确认操作可见。复核没有Critical或Important问题。

## 公开发布验证

- [三平台构建](https://github.com/apple-half/nga-reader/actions/runs/43130533598)通过，固定到`v0.1.9`提交`c91168f`；[最终验签和发布](https://github.com/apple-half/nga-reader/actions/runs/43132018975)通过，并更新三个签名索引。
- 离线签名未传入`--notes`覆盖项，三个实际生成的签名文件均使用简短App文案。重新下载[公开Release](https://github.com/apple-half/nga-reader/releases/tag/v0.1.9)十个资产，核对大小、摘要、九条校验清单和全部签名；三平台更新归档与便携ZIP逐文件相符。
- 使用软件相同代理传输实际读取三个平台的签名索引，均识别0.1.9，说明与App短文案一致；读取三次索引、零次API回退，不携带论坛或GitHub凭据。
- 在独立QA目录真实执行Windows MyGo更新，替换后程序与公开Windows ZIP一致，四份模拟设置／草稿／会话占位／无关文件保持原样。
- 以`v0.1.7`原始更新界面代码做只读overlay验证，新的简短说明可以完整阅读、安装操作可见；不替换正在使用的旧程序。同步公开索引后，完整Go套件再次通过。
- 本地保留三份与公开文件一致的免安装ZIP；测试临时副本清理，必要验证记录单独归档。

## 兼容与取舍

- 旧0.1.7／0.1.8客户端显示说明的方式无法随服务器文件直接改变；新发布的简短普通列表先改善旧版的可读性，升级后使用新弹窗。持续403的0.1.7仍需手动下载一次新版。
- 沿用现有唯一GitHub checkout和功能分支；不修改已发布0.1.8标签或资产，也不替换用户正在运行的程序与数据。
- 发布时说明必须匹配版本对应的短文案；同版本文案被维护者提前修改时会明确停止发布，应恢复该版本文案再验证，不能覆盖公开文件。
- 暂缓的小问题：历史说明如果只有HTML，当前界面会保留“完整更新说明”入口，但摘要可能为空。本次及后续规范的App说明为普通短列表，不经过该路径。
- Mac真机更新和完整系统GUI操作仍需实际使用核验；CI构建／签名及原生测试不等同于真机使用或系统安全认证。
