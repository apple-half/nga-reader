# GitHub 自动更新

用户要求从 GitHub 获取更新，并选择“启动时自动检查，有新版时提示，点击后下载安装”。继续 Windows x64、macOS arm64/amd64 免安装分发，保留设置、账号会话和草稿。旧版0.1.6及以前需手动换成带更新功能的首版。

## 方案

复用固定 MyGo v0.8.3 的签名校验、解压、文件替换和重启能力，提供符合当前外观的原生界面。自行编写替换脚本会重复现有能力，因此不采用。GitHub目录读取与签名发布使用本项目的小型封装：固定仓库 apple-half/nga-reader，只选公开、版本更高、有本平台完整签名资产的发布，支持目前的预发布渠道。

启动10秒后检查，此后每24小时检查；可在设置关闭自动检查，也可从侧栏/设置手动检查。后台发现更新以侧栏入口和提示告知，不抢占发帖编辑器。更新面板展示当前/新版本、发布说明、来源、下载进度、错误和重启入口。不得后台自动安装；只有用户点击才执行。

## 信任与发布

更新公钥固定在源码和 MyGo配置中，Ed25519私钥保存在维护者本机、Git目录之外，不上传 GitHub、聊天、Release或CI。CI只构建三个平台并将便携ZIP放入草稿。维护者从草稿下载已验证ZIP，使用命令行签名工具离线生成MyGo兼容tar.gz与每平台manifest，再上传草稿。第二次工作流只读下载草稿全部资产，验证公钥签名、大小、SHA256与归档结构后才公开。

除了MyGo的归档签名，再签名manifest的版本、平台、URL、摘要、大小和说明，防止替换说明/版本或重放旧归档冒充新版。客户端只从固定仓库的HTTPS资产地址读取，不携带NGA Cookie或GitHub凭据，拒绝跨平台资产、降级、篡改、路径穿越及私有数据。公钥与更新签名不等同于Windows商业签名或Apple公证，既有安全状态继续如实说明。

## 安装边界

下载/验证/替换由MyGo完成，文件清单不得包含data、settings.json、drafts.json、session.enc、缓存或日志。Windows更新应用文件，保留旁边数据；Mac替换.app，数据留在用户Library。只读、受保护或AppTranslocation位置不尝试修改权限或绕过系统限制，显示手动下载入口。

发帖发送中禁止安装/重启更新。安装前保存并关闭编辑器；保存失败则不安装。安装期间冻结会话变更与新发帖，并防止正常退出打断替换。完成后由用户选择立即重启或下次启动使用新版。数据目录独占锁必须在MyGo重启子进程前释放，不能依赖main返回后的defer。

## 验证

本地HTTP服务覆盖版本排序、预发布、缺少平台包、错误域名/大小/签名、超时、manifest篡改、归档路径与私人文件。原生UI测试覆盖后台提示、手动检查、下载进度、失败保留、发帖/草稿保护、重启顺序和设置迁移。用隔离目录验证MyGo实际安装保留数据，不替换用户正在使用的程序。发布0.1.7及三个免安装包，实际下载核验；Mac系统拦截和真实更新后的GUI仍保留验证边界。
