# 文字发帖与回复

用户在功能评估后要求加入发帖；已确认范围为文字新帖、普通回复、引用回复，不上传图片。沿用 Go/MyGo、原生三栏、现有主题和 Windows/macOS 便携包。

## 方案与界面

采用原生编辑器与 NGA 接口提交，复用本机登录会话。整页网页编辑器会破坏现有外观，因此不采用。板块列表顶部提供“发帖”，正文工具栏提供“回复”，每层提供“引用回复”；编辑器清楚显示账号、板块及目标帖子/楼层。新帖可以从已有板块中选择，并读取分类供标题使用。发送必须由用户点击按钮，Enter 只换行。

## 协议与状态

先读取 post.php 的发布准备信息，再提交 step=2；使用 __inchst=UTF8、__output=8，兼容 GB18030 响应。只支持 new/reply/quote。引用内容采用论坛提供的预置正文，避免手工拼装伪造楼层。

发布准备须验证实际账号和目标；新帖需要非空标题，所有操作需要非空正文。客户端编辑限制为标题128字符、正文20000字符，论坛仍可施加更严格限制。分类读取失败不得悄悄清空正文；允许手动填写论坛要求的标题前缀。

发送按钮在请求中锁定，不自动重发 POST，不跟随提交重定向重放正文。登录过期、权限或限频等明确拒绝保留草稿。网络断开、超时、无法识别的提交结果属于“结果待确认”：保留草稿并持久记录，要求用户先检查原帖/板块、主动确认后才能再次提交。成功只依赖明确的论坛完成结果，不能以 HTTP 200 或任意返回链接代替成功。审核中必须显示“已提交审核”而非“已公开”。

草稿按账号UID和操作/板块/主题/楼层隔离，保存在本机数据目录 drafts.json，原子写入、大小限制，不进入 Git/ZIP。关闭编辑器与退出程序保留草稿，成功删除对应草稿；切换账号后不展示其他账号的草稿。发送中不可改动目标、正文、关闭编辑器或退出登录，退出程序则保留待确认记录。

独立设计核对补充：在发送前必须先持久保存待确认记录，失败则不发送。发送期间冻结退出登录、Cookie导入、登录会话替换和演示切换等全部会话入口。回复的真实FID采用发布准备信息，不能以侧栏当前板块覆盖。

## 错误与兼容

验证码或论坛额外验证显示服务端提示和官方页面入口，原生正文保留；不会自动绕过验证或自动重新发布。真实发帖有外部副作用，本次自动验证使用本地模拟服务器与离线界面，不代用户发布测试内容。

## 验证与交付

覆盖三种操作、UTF8请求/GB18030响应、账号/目标隔离、明确拒绝、模糊结果、无自动重试/重定向重放、草稿跨重启恢复、双击防重、演示模式不发网络请求。检查三种主题下的编辑器和最小窗口。完成独立代码审查后构建 Windows x64 / macOS arm64 / macOS amd64 便携包，以新版本发布，保留既有0.1.5与360材料。
