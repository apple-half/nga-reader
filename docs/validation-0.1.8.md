# 0.1.8 阅读体验与更新验证

## 改进与检查范围

- 更新HTTP403已复现为未登录GitHub API额度耗尽。改用公开签名索引优先，API仅作可用性回退；签名／格式错误不回退。限额冷却、无账号凭据、大小限制和三平台索引签名均有测试。
- 已读／有新回复标记、最近100条阅读记录、旧格式迁移及账号隔离；读取失败或取消不会标记已读。只看楼主和完整帖子分别处理，不覆盖完整帖子的阅读位置。
- 原生界面测试覆盖PID／楼层定位、位置持久化、手动滚动、窗口宽度和字号变化、页码输入／全角数字／Enter／Esc、链接页码、首页／末页与未知总页数。
- 深色、浅色、NGA经典屎黄色在980×620窗口检查长标题、底部分页和弹窗；刷新保留当前页内容并提供明确重试，账号切换取消旧请求并清空旧阅读区。
- 保留图片点击才加载、发帖确认、防重复发送、草稿和更新期间的保存保护。未使用真实账号发表测试内容。

## 独立审查后的修复

审查发现三个重要问题，均先以回归测试复现失败，再修复并通过完整Go套件：

1. 退出“只看楼主”恢复原完整帖子的页码和位置。
2. 在当前阅读中调整字号或窗口宽度，按原PID／楼内位置恢复一次，之后手动滚动继续生效。
3. “从头阅读”仅在第一页读取成功后清除旧位置；失败、取消和只看楼主模式保留原完整帖子的进度。

本地验证：完整Go测试、`go vet`、登录脚本测试、18项发布脚本测试、actionlint和公开源码隐私扫描通过。正式发布还须由三平台CI构建并核验产物，再离线签名、核对公开文件和隔离Windows替换测试。

## 实现取舍与边界

- 更新索引包装原有签名元数据，保留0.1.7更新协议；外层预发布标记仅用于显示。旧客户端持续403时仍需手动下载一次0.1.8。
- 沿用现有唯一GitHub checkout和功能分支，避免再次产生本地源码副本。
- 三平台索引以非强制Git引用更新一次提交。并发修改主分支可能让索引发布失败，此时用`refresh_feed`恢复；不覆盖已公开包或标签，私钥不进入CI。
- 待完善的小问题：HTML兼容读取遇到零回复主题且无法确认总回复数时，第一次新增回复可能没有“有新回复”标记；正常提供回复总数的API读取不受影响。
- Mac由CI检查构建、包结构及ad-hoc签名，不代表已完成Mac真机更新、全部GUI或中文输入法验证。系统代码签名和360状态见[安全说明](../SECURITY.md)。
